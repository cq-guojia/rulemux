## 一、需求原话

> 「你的介绍有问题。你介绍的重点是同步到当前工作区……什么不用软链什么什么，这些对用户来说不重要。」
> 「你要换个方向去写，能把一些通用的规则给抽象出来，维护同一个源。同时支持层级下放分组。」
> 「简介你可以写简单一点，但你要去更新这个项目的 README，前面的介绍一定要介绍到痛点上去。」
> 「这个痛点实际上就是：每一个 Agent 的规则都放在不同的文件夹，每个工作区的规则也在不同的工作区，
> 一些总体的统一规则实际上很难去抽象，也很难去管理。」
> 「最上层：统一的规则。第二层：分为开发类规则和非开发类规则。第三层：在开发类下面，可以细分为
> 小程序开发的规则、后台开发的规则、C 端开发的规则；在非开发类下面，可以分为工作区的日常规则等。
> 第四层：最下面才是每个工作区单独的规则。」
> 「这个插件能帮助你管理唯一一个正源，一处修改就能同步到所有的 Agent 和所有的工作区，而且是规则复用。」

## 三、以后写介绍就按这个口径

- **痛点三句**：每家 agent 的规则目录不同 → 每个工作区又各有一份 → 真正通用的规则既抽不出来、也管不动。
- **四层结构**：统一规则 → 开发类 / 非开发类 → 细分领域（小程序 / 后台 / C 端；工作区日常）→ 单个工作区自己的规则。
- **核心卖点**：唯一真源 + **层级下放 + 规则复用** + 一处修改同步到所有 agent 与所有工作区。
- **不写**：软链、不累积、注入时机、hook 语义这类实现细节 —— 用户明确说对读者不重要（实现层仍留在 `design/`）。
