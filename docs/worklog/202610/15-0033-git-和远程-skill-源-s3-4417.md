# 20261015-0033-git-和远程-skill-源-s3-4417：git 和远程 skill 源 S3

> **创建**：2026-10-15 00:33:47（@GuoJia-Agent）

## 背景

v2 任务（`20261013-1133-…-eec8`，已结案）明确移交的两条线之一。用户 2026-10-15 原话：

> 「这两个东西没什么关系，单独建成两个吧：一个是 Trae 的 skill 介入；一个是 git 和远程的 skill 源。」

需求出处：requirements.md §六 S3「市场的贡献与跟进（管理我的源 + 跟进别人开发的 skill，比如
GitHub 上的）」。v1 skill 同步（2026-10-12 交付）明确不做远程源（skill-sync.md §三「第一版只支持
本地 skill 源」），本条补上。参照实现：npx skills 的六种源写法已逐字记录在
external/skill-ecosystem.md §二（GitHub 简写 / 完整 git URL / 仓库内子路径 / GitLab / 任意 git
URL / 本地路径 / 直链 zip-tar；私有仓库复用本机 git 凭据；无 lockfile）。

硬约束（不可破）：Go 单二进制**零第三方依赖** ⇒ 不能引 git 库；「永不淡出/不累积/不用软链」底线
⇒ 远程源也走 real copy，不走 npx skills 的 symlink canonical 模式。

## 待办

- [ ] 源写法设计：`[[skill_source]]` 的远程形态（扩展 `path` 还是新键如 `repo`/`url`；
      GitHub 简写 `owner/repo`、仓库内子路径 `/tree/<ref>/skills/<name>`、直链 zip/tar 至少要支持；
      `agents`/`workspace`/`scope`/groups 语义不变）
- [ ] 获取方式拍板（零依赖下的三选一，影响最大，先定）：
      a. spawn 本机 `git`（宿主有 git 的概率高，但规则上多一个外部依赖）；
      b. HTTP tarball（`codeload.github.com` / GitLab 等价物 + `archive/zip`+`archive/tar` 标准库）；
      c. 两者按源形态分流（git URL 走 a、简写/直链走 b）
- [ ] 缓存与更新语义：下载缓存放哪（`~/.rulemux/cache`？）、何时重新拉取、
      **无 lockfile**（与 npx skills 一致，需在文档明示「不锁版本」的代价）
- [ ] 安全边界（信任边界，不许砍）：下载大小/解压大小/文件数上限（npx skills 为 ≤10MiB/
      ≤25MiB/≤1000 文件，可借鉴）；路径穿越防护（zip slip）；私有仓库凭据处理
      （`gh` → SSH 回退、`GITHUB_TOKEN`/`GH_TOKEN`；绝不落盘明文）
- [ ] `rulemux skill` 子命令（list/update）是否同批做——v1 文档写「后续版本」，本任务拍板；
      YAGNI 候选项：`find`/市场索引接入（明确不做，见 skill-sync.md §三）
- [ ] 文档：skill-sync.md 增补远程源设计节、README §5.4/§5.5、requirements §六 S3 验收判据
- [ ] 测试：远程源单测用本地 git 仓库 + `httptest`（**不打了真网**）；上限/zip slip 用例；
      smoke 加一步本地 git 仓库作源的端到端

## 下一步

1. 先出方案再写码：把「源写法 + 获取方式（a/b/c）+ 缓存与更新语义 + 安全边界」写进
   docs/design/features/skill-sync.md 新节（§八 远程源），获取方式一节必须给出取舍结论——
   `git` 二进制在宿主机的实际存在率 vs HTTP tarball 的覆盖度（GitHub/GitLab 都支持
   codeload 式 tarball；任意 git URL 只有 spawn 能覆盖）；
2. 方案经用户拍板后进 config 层（`[[skill_source]]` 新键解析 + 校验），再进引擎
   （BuildSkillPlan 的源根从「本地目录」扩展为「本地目录 | 缓存目录」）；
3. 凭据与上限作为独立一步最后做（信任边界，单独用例）。
