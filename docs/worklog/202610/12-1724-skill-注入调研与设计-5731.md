## 过程

### 一、市场预调研（2026-10-12，web 检索 + README 抓取）

**最成熟候选：vercel-labs/skills（npx skills，skills.sh，MIT，约 34k★/570 commits，2026-10-12 页面数据）**，README 关键事实：

- 定位「The CLI for the open agent skills ecosystem」，支持 75+ agent（Claude Code / Cursor / Codex / OpenCode / Copilot / Windsurf / Gemini CLI / Trae 等）。
- 安装目标：**项目级（默认）`./<agent>/skills/`，相对运行目录（cwd）**；**全局 `-g` → `~/<agent>/skills/`**；README 明示 Eve / PromptScript 仅项目级。未见「安装到任意指定工作区」的参数 ⇒ 用户「不支持推送到某一个工作区」的印象**基本属实**（项目级 = 当前目录，要推别的工作区得 cd 过去）。
- 安装方式：symlink（README 推荐，canonical 副本在 `~/.agents/skills/`）或 copy。
- 源：GitHub 简写 `owner/repo`、完整 Git URL、仓库内子路径 `/tree/<ref>/skills/<name>`、GitLab / Azure DevOps / 任意 git URL（SSH）、本地路径、直链（SKILL.md 或 zip/tar/tgz）；私有仓库复用本机 git 凭据（gh → SSH 回退，`GITHUB_TOKEN`/`GH_TOKEN`）。
- 市场兼容：发现 `.claude-plugin/marketplace.json` / `plugin.json` 即按 Claude 插件市场生态解析。
- 更新：`npx skills update [-g|-p|-y]` 拉最新；**无 lockfile**（版本不锁定）。另有 `remove` / `list` / `find` / `init` / `use`（不安装直接用）。
- 限制：下载 ≤10 MiB / 解压 ≤25 MiB / ≤1000 文件（可用 `SKILLS_DOWNLOAD_MAX_BYTES` 等覆盖）；发现深度默认 3 层（`--full-depth` 扩展）；`metadata.internal: true` 默认隐藏；默认遥测（`DISABLE_TELEMETRY=1` 关）。
- **没有的**：配置驱动的「一份源 → N agent × M 工作区」扇出、SessionStart hook 实时同步、工作区账本、残留清理（它靠 symlink 指向 canonical copy，删除即 remove 命令）。

**语义差异（设计关键，预调研结论）**：rules 会话开始静态全量加载（static prefix）；skills 渐进式披露——启动只载 name+description，模型按名调用时才读 SKILL.md 全文，且 skill 是**目录**（`SKILL.md` + 可选 scripts/references/assets）。⇒ skills 只能走「真实拷贝进原生 skills 目录」（Tier-1 思路沿用）；hook 注入全文会撑 token 且破坏按名调用；现有 `internal/engine` 的「文件 + `__rulemux__` 前缀」需扩展为「目录树同步 + 残留目录清理」。

### 二、补调研结果（2026-10-12，已全部回写 `docs/design/external/skill-ecosystem.md`）

1. **npx skills 兼容表（README 逐字）**：`codebuddy` / `claude-code` / `trae` 在表；**workbuddy / dsh / DeepSeek 不在表**。OPTIONS 只有 `-g/-a/-s/-l/-c/-y/--all`，**无 `--target`/`--workspace`/`--dir`** ⇒「推送到指定工作区」确实没有，用户印象坐实。且其默认 symlink 模式（canonical 副本 `~/.agents/skills/`）与 rulemux「不用软链」底线冲突。
2. **本机实测（强证据）**：
   - `/root/.codebuddy/skills/hindsight-coding-agent/` 存在 ⇒ CodeBuddy 用户级 skills 目录坐实；`/root/.codebuddy/skills-marketplace/` 为官方市场组件（100+ 技能目录）；
   - `/root/.trae-cn/skills/hindsight-coding-agent/` 存在 ⇒ **Trae CN 用户级 skills 落点是 `~/.trae-cn/skills`（不是 README 的 intl 口径 `~/.trae/skills`）**，与 hook 落点同规律；
   - genie 扩展产物含 `"skills-changed"` 事件字符串 ⇒ skills 疑似可热重载（待 canary，若坐实则 skill 不需要 rules 那种「新开会话」提示）；
   - CodeBuddy marketplace 技能 SKILL.md frontmatter：`name`/`display_name`/`description`(+zh/en)/`version`/`allowed-tools`；用户自装技能用 Anthropic 简式同样在装 ⇒ 两种 frontmatter 都接受。
3. **WorkBuddy skills**：多篇二手一致指向 `~/.workbuddy/skills/<name>/SKILL.md`（CSDN 2026-10、腾讯云 2026-06），本机无此 app 无法实测 ⇒ 🔴。工作区级未知。按 `agent-rules-dirs.md` §5.4 教训，两级必须分别实测。
4. **dsh skills**：二手（阿里云 2026-10-03 引官方 skills 子系统文档 + CSDN 2026-08）称项目技能放项目根 `.dsh/skills` 或 `.agents/skills`、**不递归**；dsh 插件可经 `ctx.skills` 注册技能 ⇒ 🔴 待官方文档复核。
5. **用户级 rules 目录**（全局注入前置）：Claude `~/.claude/CLAUDE.md`（🟡 文档级）；CodeBuddy 用户级规则落点仍「未确定」（与 `agent-rules-dirs.md` §二既有记录一致）；Trae `~/.trae-cn` 无 rules 目录；dsh `$DSH_HOME/rules`（既有记录）⇒ 🔴/🟡 分级见外部文档 §五。
