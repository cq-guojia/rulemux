## 背景

用户 2026-10-14 把 rulemux-dsh 更新到 0.4.0 后发现：装了插件、也重启了 dsh，但 **rules 没有任何注入**。插件既没报错也没提示，就是静默不注入。用户原话：「这次更新了之后就没有注入了……我升级那个插件，没注入。」（插件 0.4.0 装载日志显示从未尝试 `inject --agent dsh`，也未报任何就绪失败。）

排查前先排除了用户操作：经核对 `~/.rulemux/config.toml` 完全正常（最初被误判为「配置坏了」，已更正）。根因在插件自身的版本判定。

## 待办

无待办——代码已交付、随 rulemux-dsh 0.4.1 / 0.4.2 发出，真机验收通过（2026-10-14，用户「真机已经通了」）。

## 下一步

任务已随 0.4.2 发出并真机验收通过，无后续步骤。本工作文档仅作结案归档。

## 过程

- **根因**：`dsh-plugin/index.mjs` 的 `cliOk()` = `版本满足 REQUIRED_CLI` **或** `knowsDsh()`（`--help` 匹配 `dsh`）。`REQUIRED_CLI` 当时为 `>=0.3.1`，而 `0.3.1`~`0.4.1` 全都在 `--help` 列出 `dsh` ⇒ 被当成「CLI 合格」⇒ **不触发自动升级**。但这批旧 CLI 的配置解析器**不支持 rulemux 配置里的行尾 `#` 注释**（该能力 0.4.2 才引入），读 `~/.rulemux/config.toml` 会 `exit=1` 报 `references undefined file group "..."`。于是插件以为 CLI 够用、不去升级、却每轮因配置解析失败而静默不注入。
- **实证**（本机拉 npm 包，用同一份正常配置测）：`rulemux@0.3.2` → exit=1；`0.4.1` → exit=1；`0.4.2` → exit=0，输出 115 行规则。报错与用户容器里一字不差。
- **修复（提交 `2d178f7`，rulemux-dsh 0.4.1）**：`cliOk()` 改为**以版本为准**——低于 `REQUIRED_CLI` 一律升级，`knowsDsh()` 仅在版本完全读不出时兜底；`REQUIRED_CLI` 提到 `>=0.4.2`；新增回归测试「dsh-aware 但过旧的 CLI 必须显式失败」（不再静默不注入）。
- **实机暴露第二层**（容器 `7a3a9f524a94`，2026-10-14）：装 0.4.1 后插件**确实去自动升级 CLI** 了（证明修复生效、不再静默），但装不上：
  - `pnpm add -g rulemux@latest` → exit 1，`ERR_PNPM_GLOBAL_BIN_DIR_NOT_IN_PATH`（pnpm 全局 bin 目录 `/root/.local/share/pnpm/bin` 不在 PATH）；
  - `npm install -g rulemux@latest` → exit 1，`EEXIST /usr/local/bin/rulemux`（该 0.3.0 是**手工放置**、非 npm 管理，npm 不敢覆盖）。
  - 失败在 0.4.1 里**显式报错**呈现（不再是静默不注入）。
- **修复（提交 `e245f6d`，rulemux-dsh 0.4.2）**：`installCli()` 增加末位兜底 `npm install -g --force`（npm 官方对 EEXIST 的推荐解法），可覆盖手工放置的 `rulemux`；单测 5/5 通过（含「手工文件挡住普通安装时 `--force` 兜底成功注入」用例）。
- **同步文档**：`AGENTS.md` 第 5 条（CLI 与 dsh 插件两条独立发布线须配对推进）；`docs/design/features/dir-sync.md` 就绪步骤①写明下限 `>=0.4.2` 与 `--force` 兜底。

## 结论

- 根因已修：`cliOk()` 不再被 `knowsDsh` 骗过；`REQUIRED_CLI` 提到 `>=0.4.2`；`installCli` 带 `npm --force` 兜底。已随 rulemux-dsh 0.4.1 / 0.4.2 发出。
- 真机验收（2026-10-14，容器 `7a3a9f524a94`）：用户确认「真机已经通了」，任务完成。
- 遗留 / 注意：① pnpm 在该宿主 dsh 进程内的全局 bin 目录不在 PATH，pnpm 升级路径实际不可用，目前完全依赖 npm（含 `--force`）；若想用 pnpm 需先解决 PATH。② 判定逻辑写死在插件 `dsh-plugin/index.mjs`，CLI 侧改不了——故凡改动「CLI 获取 / 版本判定」都必须同步发 `dsh-vX.Y.Z`（已写入 AGENTS.md 第 5 条）。③ 用户本机 `/usr/local/bin/rulemux` 为手工放置的 0.3.0，会持续存在；新版插件靠 `--force` 覆盖它，无需手动清理。
