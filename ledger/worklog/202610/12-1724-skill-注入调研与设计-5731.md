## 过程

### 一、市场预调研（2026-10-12，web 检索 + README 抓取）

**最成熟候选：vercel-labs/skills（npx skills，skills.sh，MIT，约 34k★/570 commits，2026-10-12 页面数据）**，README 关键事实：

- 定位「The CLI for the open agent skills ecosystem」，支持 75+ agent（Claude Code / Cursor / Codex / OpenCode / Copilot / Windsurf / Gemini CLI / Trae 等）。
- 安装目标：**项目级（默认）`./<agent>/skills/`，相对运行目录（cwd）**；**全局 `-g` → `~/<agent>/skills/`**；README 明示 Eve / PromptScript 仅项目级。未见「安装到任意指定工作区」的参数 ⇒ 用户「不支持推送到某一个工作区」的印象**基本属实**（项目级 = 当前目录，要推别的工作区得 cd 过去）。
- 安装方式：symlink（README 推荐，canonical 副本在 `~/.agents/skills/`）或 copy。
- 源：GitHub 简写 `owner/repo`、完整 Git URL、仓库内子路径 `/tree/<ref>/skills/<name>`、GitLab / Azure DevOps / 任意 git URL（SSH）、本地路径、直链（SKILL.md 或 zip/tar/tgz）；私有仓库复用本机 git 凭据（gh → SSH 回退，`GITHUB_TOKEN`/`GH_TOKEN`）。
- 市场兼容：发现 `.claude-plugin/marketplace.json` / `plugin.json` 即按 Claude 插件市场生态解析。
- 更新：`npx skills update [-g|-p|-y]` 拉最新；**无 lockfile**（版本不锁定）。另有 `remove` / `list` / `find` / `init` / `use`（不安装直接用）。
- 限制：下载 ≤10 MiB / 解压 ≤25 MiB / ≤1000 文件（可用 `SKILLS_DOWNLOAD_MAX_BYTES` 等覆盖）；发现深度默认 3 层（`--full-depth` 扩展）；`metadata.internal: true` 默认隐藏；默认遥测（`DISABLE_TELEMETRY=1` 关）。
- **没有的**：配置驱动的「一份源 → N agent × M 工作区」扇出、SessionStart hook 实时同步、工作区账本、残留清理（它靠 symlink 指向 canonical copy，删除即 remove 命令）。

### 三、CodeBuddy bundle 深挖（2026-10-12，本机安装产物逐段核查）

对象：`~/.codebuddy-server-cn/bin/stable-757a5b2fd56bc7e1fcabb38b58d2ac1694f78f6d/extensions/genie/out/extension/index.js`（21 MB，构建于 2026-09-20）。结论已回写 `external/agent-rules-dirs.md` §5.5 与 `external/skill-ecosystem.md` §三·续，此处记要点与出处：

1. **用户级 rules 落点坐实**（销 external §六 项5）：`userBasePath=join(homePath,USER_DATA_DIR_NAME,"rules")`；`DefaultRuleManager(projectBasePath, userBasePath, hiddenProjectBasePath, …)` 三路径共同加载；`watchDirectory(userBasePath,"user")`；`RuleScope.USER` 有写权限检查。迁移史：`sharedDataPath/.rules`（`<server>/Data/Public/.rules`）→ `~/.codebuddy/rules`（`migrateOldRules` + `.rules-migrated` 标记）。
2. **用户级 skills 目录**：`userSkillsDir=join(homedir(),".codebuddy","skills")`（市场安装器默认目标，`installSkill` 按名加锁）；本机 `~/.codebuddy/skills/hindsight-coding-agent` 在装且**本会话装载可用（活证）**。
3. **工作区 skills 目录**：`getProjectSkillsDir()=join(workspaceFolders[0].fsPath, WORKSPACE_DATA_DIR_NAME, "skills")`；本仓库 `.codebuddy/skills/koc-code-doc-progress` 在装。
4. **`CODEBUDDY_CONFIG_DIR` 只影响 settings.json**：`getCodeBuddyHomeDir()`（env 优先）与静态 `join(homedir(),…)` 两套并存；rules/skills 用户级路径用后者 ⇒ 不跟随 env。
5. **官方市场第三方源 = 不支持**（销 external §六 项7）：市场=单一官方 git 仓库（内网 CNB `cnb.woa.com/genie/skill-marketplace`）；`marketplace.json` 293 个技能的 `source` 字段全是库内目录名、无外部 URL；更新=GUID 版本轮询+失败退避；贡献=给仓库提 PR。
6. **`skills-changed`** 只见于 webview `postMessage`（UI 刷新类），非会话热重载证据；`SKILL_FILE_NAMES=["SKILL.md","skill.md"]` 大小写都认。

### 四、CodeBuddy ↔ WorkBuddy 同源模型（2026-10-12，bundle 代码级）

bundle 内 38 处 `workbuddy` 引用 ⇒ **两者是同一套代码库的两个品牌**，用户级目录名由 product 配置 `dataFolderName` 决定（`getBrandUserDataDirName()`，兜底 `.codebuddy`）。本机 CN 安装 `product.json` 为 `dataFolderName=".codebuddycn"` / `applicationName="buddycn"`，但实际生效目录仍是 `~/.codebuddy`（活证：settings.json 钩子、skills、rules 注入均在此且被读取）⇒ 品牌函数与静态常量两套并存，以静态常量为生效口径。

- skills 用户级合并**单向**：`resolveUserSkillsDirs()` 仅品牌为 `.codebuddy` 时并列 `.workbuddy` ⇒ CodeBuddy 读两家、WorkBuddy 只读自己的。
- 工作区级两家共享：`WORKSPACE_DATA_DIR_NAME=".codebuddy"`（bundle 内仅此一个值），与 rules 侧 §5.4 实测（WorkBuddy 读 `.codebuddy/rules`）互印。
- rules 侧无并列逻辑（`userBasePath` 单目录）⇒ 用户级 rules 不合并。
- **对设计的改变**：用户级注入必须双写（`~/.codebuddy/…` + `~/.workbuddy/…`）才覆盖两家；工作区级维持单写。已回写 `skill-sync.md` §二.2/§二.3。
- WorkBuddy 侧仍待 Mac 实测（settings.json 与工作区 rules 已于 2026-10-09 坐实，§5.4）。

### 二、补调研结果（2026-10-12，已全部回写 `docs/design/external/skill-ecosystem.md`）

1. **npx skills 兼容表（README 逐字）**：`codebuddy` / `claude-code` / `trae` 在表；**workbuddy / dsh / DeepSeek 不在表**。OPTIONS 只有 `-g/-a/-s/-l/-c/-y/--all`，**无 `--target`/`--workspace`/`--dir`** ⇒「推送到指定工作区」确实没有，用户印象坐实。且其默认 symlink 模式（canonical 副本 `~/.agents/skills/`）与 rulemux「不用软链」底线冲突。
2. **本机实测（强证据）**：
   - `/root/.codebuddy/skills/hindsight-coding-agent/` 存在 ⇒ CodeBuddy 用户级 skills 目录坐实；`/root/.codebuddy/skills-marketplace/` 为官方市场组件（100+ 技能目录）；
   - `/root/.trae-cn/skills/hindsight-coding-agent/` 存在 ⇒ **Trae CN 用户级 skills 落点是 `~/.trae-cn/skills`（不是 README 的 intl 口径 `~/.trae/skills`）**，与 hook 落点同规律；

   - CodeBuddy marketplace 技能 SKILL.md frontmatter：`name`/`display_name`/`description`(+zh/en)/`version`/`allowed-tools`；用户自装技能用 Anthropic 简式同样在装 ⇒ 两种 frontmatter 都接受。
