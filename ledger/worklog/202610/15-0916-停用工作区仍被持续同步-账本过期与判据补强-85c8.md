## 背景

用户原话（2026-10-15）：

> 「如果我在 Work 8 里面把这个工作区删了，但文件目录还在，我们在执行同步命令时，它还会不停地往里面推。实际上，这个工作区可能我不在 Work 8 上用了，而是改在 Trae 上用。这个时候即便我改了配置，那个账本其实还在，而且因为目录还在，账本就一直不会丢掉。我觉得这个机制有点问题。」

两个诉求：

1. 同步到涉及某 agent（如 workbuddy）的工作区时，有没有判断用户是否还装着该 agent 的钩子？初始化时若 agent 已卸载，就不该同步。
2. 能否读到 agent 自己建立的工作区清单（workbuddy / codebuddy / dsh），而不是靠「文件夹是否存在」判断。用户把 agent 分三类：自研客户端（workbuddy）、VSCode 集成（codebuddy / trae / code）、完全开放（dsh，插件交付）。

机制现状（代码取证，2026-10-15，行号为当时值）：

- 账本只增不除：GC 仅清 ENOENT 条目（`internal/cmd/sync.go:445-452`、`:467-474`）。
- 裸 `sync` / `sync --all` / 顺手同步的投递判据 = **账本(ws) ∪ 配置点名 − off，无钩子检查**（`sync.go:539-565` bareTargets、`:455`、`:348` cascade）。
- 钩子判据仅两处使用：共享目录并集 `hookedPeers`（`sync.go:400-421`）与账本哨兵 `*` 展开（`sync.go:506-512`）。
- `off` 只由 `rulemux uninstall` 写、`init` 才清（`uninstall.go:182-185`、`init.go:347-359`）⇒ 改配置无效，唯一 in-band 断联是 `rulemux uninstall --agent X`。
- 钩子是 **user 级全局**（`docs/design/architecture.md` §五）⇒ 删工作区不动钩子文件 ⇒ 钩子门禁治不了主诉场景。

| Agent | 类型 | 按工作区建档的 store（本机实测） | 路径还原 | 语义 |
|---|---|---|---|---|
| codebuddy | VSCode 集成 | `~/.codebuddy-server-cn/data/User/globalStorage/tencent-cloud.coding-copilot/genie-history/<base64(ws)>/{current.json, conversations/, backups/}`，45 条 | ✅ 精确（标准 base64，`=`→`_`） | 使用历史；`current.json.lastUpdated` = 最近一次会话时间 |

| workbuddy | 自研客户端 | 本机（Linux）无 server data 目录，仅 `~/.workbuddy/{rules,skills,settings.json}`；与 codebuddy 同代码库双品牌（`docs/design/external/agent-rules-dirs.md` §5.5）⇒ Mac 上预期同构 genie-history | 待验证 | 🔴 需 Mac canary |
| dsh | 完全开放 | 无 `~/.dsh`；插件按 `agent.session.header.cwd` 定位（`dsh-plugin/index.mjs:447-449`） | — | rules 注入不落盘、账本不记 Tier-2（`sync.go:517`）；skills 只在真开会话时落 ⇒ **天然免疫此问题** |

三条关键旁证：

1. **全是 append-only 历史，不是活列表**：genie-history 中 `/root/CodeBuddy/2026*`、`/code/koc-weapp/*` 等目录在盘上已不存在，条目仍在 ⇒ 只能证明「这个 agent 在这个工作区开过会话、最近一次在何时」，**不能**证明「用户当前还把它列在工作区里」。
2. **VSCode 标准的「最近打开」拿不到**：真源是 `User/globalStorage/state.vscdb`（SQLite，key `history.recentlyOpenedPathsList`）或旧版 `storage.json` —— 本机全盘搜索 **0 命中**；且 SQLite 读取与项目「零第三方依赖」硬约束冲突。
3. **共享目录的文件集由钩子决定、不由账本决定**：`.codebuddy/rules` 落什么文件由 `hookedPeers`（钩子）算并集（`sync.go:249`）⇒ 停用 workbuddy 账本条目的实际效果主要是：用户级目录不再被刷新、报告不再出现它、防住「所有 agent 都停了还继续推」；文件级收敛现有并集逻辑已覆盖。

本机钩子现状（佐证用户场景的三 agent 并存）：`~/.codebuddy/settings.json`（`--agent codebuddy`）、`~/.workbuddy/settings.json`（`--agent workbuddy`）、`~/.trae-cn/hooks.json`（`--agent trae`）。

### 设计选项（待拍板）

| 选项 | 做法 | 成本 | 能治 | 不能治 |
|---|---|---|---|---|
| A. 账本刷新时间戳 + 过期 | 账本 v3：`(ws, agent)` 记 `lastSeen`，仅 hook 触发 / 在该 ws 手动 sync 才刷新（`sync --all` 不刷新）；超 N 天未刷新的条目在 `sync --all` / 裸 sync / 顺手同步中停推（报告一行），条目保留供 uninstall 回访 | 小（ledger v3 + 三个展开点 + 测试） | 主诉全场景；纯我方、零 agent 逆向 | 阈值内误停（下次开会话即自愈） |
| B. 读 agent 侧档案 | 按 agent 解析 genie-history / memory-projects 作在用判据 | 大（每家路径/编码不同、随版本漂移、workbuddy 待 canary、trae slug 歧义） | 与 A 叠加更准 | 历史≠活列表，仍需陈旧化 |
| C. 钩子门禁补全 | 账本展开处加 `hookInstalled` | 极小 | 钩子文件被删 / agent 配置被清 | 主诉（钩子是 user 级全局） |

推荐 A（可顺带做 C）：hook 触发本身就是「该 agent 确实在该工作区开会话」的 ground truth，时间戳过期是最贴合问题本质又完全自洽的方案。

### 拍板结果

- **B 方案（读 agent 侧工作区档案）否决**：能读到的全是 append-only 历史、非活列表，且随 app 版本漂移、每家路径/编码不同（见 `docs/design/external/agent-workspace-lists.md` §一/§二）。即使用上也必须叠加陈旧化，与 A 重叠。
- **A 方案（账本 lastSeen + 30 天过期）采用** —— 主修复。
- **C 方案（钩子门禁补全）采用** —— 仅作补充（治「agent 整个被全局卸载」场景，治不了主诉）。

### 实现落点

**账本 v3（`internal/state/ledger.go`）**

- 新增 `Seen map[string]map[string]int64`（ws→agent→unix 秒，`omitempty`）：平行保留原 `Agents`，不把值改成 struct，避免连锁改动。
- 老账本无 `Seen` ⇒ 读为 nil ⇒ `IsStale` 保守返回 false（照常推送），**升级无缝、不丢条目**。
- `Record(ws, agent)`：保留原签名，落盘时 `see()` 刷新时间戳 —— 钩子触发 / 手动 sync / init 都是「在用」信号，天然满足刷新规则。
- 新增 `Touch(ws, agent)`：只 `add` 不刷新 Seen —— 专供 `sync --all` 落盘点，防例行同步把 lastSeen 永远续命。
- 新增 `IsStale(ws, agent) bool`：Seen 缺失 / 哨兵 / 未知 ⇒ false（保守）；否则 `now - Seen > StaleAfter`。
- 新增 `const StaleAfter = 30 * 24 * time.Hour`（默认 30 天，后续可升配置项）。
- `Save` 据 `Agents` 重建 `Seen`（丢孤儿时间戳）；`ForgetAgent` / `Prune` 同步清对应 `Seen`。

**门禁同点落地（`internal/cmd/sync.go`）**

- `agentsFromLedger` 改签名为 `(l state.Ledger, ws string)`（ids/off 内部从 `l` 取）；非哨兵分支对解析出的每个 agent 加两道判据：
  - **C**：`if !hookInstalled(a, ws) { continue }`（钩子已全局卸载则跳过）；
  - **A**：`if l.IsStale(ws, a.ID) { stderr 一行提示; continue }`（过期则跳过，条目保留供 uninstall 回访）。
- 哨兵 `*` 分支维持现状（本来只收 hookInstalled 的 Tier-1）。
- 三处调用点（bareTargets / syncAll / cascade）改传 `l`。
- **刷新分流**：`Sync` 落盘记账处 `requestedID=="" || e.id==requestedID` → 用 `Record`（刷新，覆盖 hook 点名 + 手动）；否则（cascade 同组他人）→ 用 `Touch`（不刷新）。`syncAll` 落盘记账一律 `Touch`。
