## 结论

### 拍板（2026-10-15，@GuoJia-Agent）

- **方向**：走「嫁接」，否决「rulemux 自建 fetch 市场客户端」（方向 1）；不等市场开放任意目标目录（Issue #130 不支持）。外部（git/npm/市场）管抓取，rulemux 只管「拉到 staging + 选择性 fan-out」。
- **配置**：不引新源键，`[[skill_source]]` 的 `path` 多态自动识别：本地目录 / `gh:owner/repo` / 完整 git URL / `npm:pkg`；新增顶层 `fetch_timeout`（默认 30s）。传输（SSH/HTTPS）由 URL 决定，rulemux 不替选。
- **staging**：`~/.rulemux/skills/<key>/`（`owner-repo`/`npm-pkg` 派生），clone 根即 skill 源根。
- **拉取时机**：日常 sync 零网络；首次 sync 惰性抓取；hook 模式阻塞但带 `fetch_timeout`，超时/失败 → 警告 + 跳过该源、继续、下回再试。
- **升级**：不自动跟新；显式 `rulemux skill update [<key>|--all]` 原地 `git pull`（不删重克、不叠加），上游删除靠现有 prune 传导；损坏才 `rm` 重 clone。与 requirements §55–57「不自动更新、手动触发」同哲学，绝不进 hook。
- **命令面**：`skill list` + `skill update` 纳入本轮（S3「跟进上游」硬必需）；市场索引接入仍不做。
- **范围**：git 优先（覆盖 GitHub + 市场镜像）；npm 为 follow-up；zip/tar 直链 YAGNI。
- **信任边界**：解压 ≤25MiB / ≤1000 文件、zip slip 防护、凭据走本机 git/npm 不落盘。

设计正文见 skill-sync.md §八。
