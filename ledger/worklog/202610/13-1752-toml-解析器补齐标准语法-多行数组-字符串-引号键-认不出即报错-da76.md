## 背景

用户转述另一 Agent 排查并定性：「TOML 支持，rulemux 不支持。多行数组
`workspace = [ 换行 ]` 标准 TOML 读到 ['/tmp/aaa/*', '/tmp/bbb/*']，rulemux 读成空 →
[all workspaces]。原因和上次行尾注释同一类：自写逐行解析器只认自己那条极简子集，
单行数组能读，多行数组读不到且不报错（静默当空）——这才是危险处。」
用户批示：「你既然用这个标准，你就得支持这个标准的所有写法……好好检查检查。」

按 TOML 1.0 审计当前 `internal/config/config.go`，确认 8 类静默/偏离问题：

| # | 标准写法 | 现状 | 后果 |
|---|---|---|---|
| 1 | 多行数组 | 只读首行 `[` → parseArray 返 nil | workspace 空 = **所有工作区**（最危险） |
| 2 | `["/rules/a,b.md"]` | parseArray 裸按 `,` 切 | 路径被切成两段垃圾，静默复制错文件 |
| 3 | 引号键 `"path" = ...` | key 带引号不匹配 switch | 整条忽略；agents 被忽略 = 投全部 agent |
| 4 | `"""..."""` / `'''...'''` | unquote 只剥一层引号 | 值变垃圾路径 |
| 5 | 文件头 UTF-8 BOM | 首行不匹配 `[[` 前缀 | **第一张表整表静默丢失** |
| 6 | 同表重复键 | 后者静默覆盖 | TOML 规定非法 |
| 7 | 表内键拼错（`agent` 漏 s） | 未知键静默忽略 | agents 空 = 投全部 agent |
| 8 | 基本串转义/非法转义 | 不处理也不报 | 偏离标准 |

约束：零第三方依赖（`docs/design/features/config-groups.md:15` 明文禁止引 TOML 库，
NAS 离线可 build）⇒ 手写完整解析层，不引库。
